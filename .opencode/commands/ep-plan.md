# S6.0 · 씬 플랜 표

**씬을 한 줄이라도 저작하기 전에 이 표를 완성한다.** 이 게이트가 없으면 방 인젝터 1종을 씬 7개가
돌려쓰고 "궁중" 씬에 궁궐 요소가 0개가 된다 — 실제로 일어난 일이다(지뢰 #62).

보유 자산 인덱스: @props-catalog.md

## 표를 `scenes.js` 상단 주석에 쓴다

```
| 씬 | 문장 요지 | 장소(고유명) | 시간대 | 배경 소스 | 앵커 소품 | 캐릭터 |
```

씬 경계는 S5가 출력한 **문장 테이블**을 따른다.
씬 start = 문장 start − 0.2~0.4s(리드), dur = 다음 씬 start까지 + 0.45(TRANSITION).

## 각 열의 규칙

**장소 — 고유명으로 쓴다.**
"실내"·"궁중" 같은 범주어 금지. "죄인의 처소 방 안"·"궁궐 정전 앞마당"처럼
**앵커 소품이 자동으로 도출되는 수준**까지 구체화한다.
장소 칸을 채웠는데 앵커 소품 칸이 안 나오면 장소가 덜 구체적인 것이다.

**배경 소스 — 카탈로그 복사가 기본.**
`props-catalog.md` §3(건물)·§5(지형지물)와 `episodes/*/index.html`에서 찾아 **출처 파일을 표에 적는다.**
신규 배경은 신규 소품과 같은 절차(구성 요소 목록화 → 검수 → 카탈로그 등재).

**캐스팅 — rig 6종 안에서만.**
host / king / admiral / militia / lady / kid.
모자 변주: king `hat:"myeonryu"`, militia `hat:"samo"|"paeraengi"|"gulgeon"`.
여성=lady(왕비는 `royal:true`), 아이=kid(w×0.6~0.7).
**6종 밖의 새 variant는 이 파이프라인 범위 밖이다** — 필요하면 사용자에게 알리고 멈춘다.
신분이 바뀌는 서사면 **모자까지 갈아입힌다**(지뢰 #11).

## 표를 다 쓰고 나서 세어 본다 (하나라도 걸리면 표를 고친다)

- [ ] distinct 배경 ≥ **3종** (아웃트로 제외)
- [ ] 동일 배경 연속 ≤ **3씬** — 4씬째는 줌·시간대·다른 벽면으로 변주
- [ ] 배경이 같은 연속 씬에는 표정·포즈·신규 소품 중 **≥1이 눈에 보이게** 바뀐다 (빈 방에서 좌표만 바뀌는 씬 금지)
- [ ] 무인(캐릭터 0명) 씬 연속 ≤ **2**, 인포그래픽 목적일 때만 — 문장에 행위 주체가 있으면 rig를 세운다
- [ ] 문장이 장소·상황 전환을 말하는 지점에서 배경도 바뀐다
- [ ] 앵커 소품이 **facts.md와 모순되지 않는다** — 그 시대에 그 물건이 있었는지 확인
      (엽전을 조선 전기에 그렸다가 시대착오로 적발된 적 있다, 지뢰 #27)

## 배경 인젝터 emit 순서를 미리 정한다 (지뢰 #69)

풀블리드 밴드(하늘·지면·벽·바닥)는 **항상 그 위에 서는 구조물보다 먼저** emit한다.
권장 순서: `하늘 → 지면 → 지면 디테일 → 원경(담·능선) → 중경 건물 → 전경 소품`

각 요소의 `bottom + height`를 세로로 나열해 뒤에 오는 밴드가 앞 요소의 y구간을 삼키는지 계산한다.
(`node bin/check_composition.mjs`가 자동으로 검사하지만, 표 단계에서 정해 두면 재작업이 없다)

표를 STATE.md에도 복사한다. 다음: `/ep-scene 1`
