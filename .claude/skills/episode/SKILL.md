# 삼십초 역사 — 원커맨드 에피소드

주제 입력 → `renders/<slug>.mp4` + 업로드 메타. 악플 3종(사실 오류·어눌한 말투·고증 논란)은 각각 게이트(S3·S4·S8)로 차단한다. **PROJECT-NOTES.md를 먼저 읽을 것** — 지뢰 원문과 아키텍처가 거기 있다.

## 포맷 (YouTube Shorts)

- **1080×1920 세로.** 파일럿(임진왜란)은 1920×1080 가로였다 — 새 에피소드는 세로로 제작하고, 파일럿의 배경 모티프(한옥·지도·바다·황혼 언덕·아웃트로)는 재배치해서 재사용한다: 캐릭터를 크게(w 380~480px), 상하 스택 구도, 배경 오브젝트는 상단 1/3.
- **Shorts 세이프존**: 우측 ~140px(액션 버튼)·하단 ~320px(제목/채널 UI)에 자막·스탬프 금지. `.cap-wrap`은 `bottom: 380px` 기준.
- 길이 30~35s. 씬 4~5개 + 아웃트로.

## 파이프라인

### S0. 입력 확인
- 주제 + 에피소드 번호(시리즈 넘버링) + 이전 편 예고와의 연결 여부.
- **소재 거부 목록**: 동북공정 인접(고구려·발해 귀속 등 현재진행 분쟁 프레임), 근현대 정치(해방 이후), 위안부·독도처럼 정확해도 진영 싸움이 붙는 주제. 야사는 "야사임"을 자막에 명시하면 허용.

### S1. 사료 리서치 → `episodes/<slug>/facts.md`
- WebSearch/WebFetch로 수집. 우선순위: 우리역사넷(contents.history.go.kr) > 한국민족문화대백과(encykorea.aks.ac.kr) > 조선왕조실록DB(sillok.history.go.kr) > 기타.
- 산출: 사실 목록(연도·수치·인명·인과), **주장마다 출처 URL 2개**. 출처 1개뿐인 흥미 주장은 "야사/설" 라벨.
- 여기서 훅 후보 3개를 같이 뽑는다 (역설·반전·의외 수치).

### S2. 대본 → `script.txt`
구조 (한 줄 = 한 문장 = 씬 경계 후보):
```
1행  훅 (0–2s): 결말·역설 먼저. "○○한 왕이 있었습니다" / "조선 최악의 아침" 형.
     "오늘은 ~를 알아보겠습니다" 형 도입 금지.
2–5행 상황 → 전개 → 반전 1개. 에피소드당 핵심 사실 1개·반전 1개만.
6행  펀치라인 (여운 or 유머).
7행  고정 아웃트로: "삼십 초 역사. 다음 편이 궁금하면, 구독." (+ 다음 편 예고 변형 가능)
```
구어체 규칙 (어눌함 게이트 1/2):
- 문장 ≤ 15어절, 총 70~85어절 (≈2.5어절/s → 30~35s).
- 종결어미 다양화: ~습니다 연속 3회 금지, ~했죠/~인데요/명사 종결 섞기.
- **숫자·단위는 TTS가 읽을 한글로 표기** (십오만, 이십 일). 자막 표시형(15만, 20일)은 S5에서 변환.
- 소리 내어 읽었을 때 걸리는 문장은 다시 쓴다.

### S3. 팩트체크 게이트 (사실 오류 차단)
- 대본의 모든 사실 주장(연도·수치·인명·인과)을 추출 → facts.md와 1:1 대조.
- facts.md에 없는 주장 = 대본에서 삭제하거나 S1로 돌아가 출처 2개 확보.
- 판정 기록을 `episodes/<slug>/factcheck.md`에 남긴다 (주장 → 출처 매핑 표).
- 통과 전에는 S4로 넘어가지 않는다.

### S4. TTS + 귀검증 (어눌함 게이트 2/2)
```bash
uvx edge-tts --voice ko-KR-InJoonNeural --rate=+6% --file script.txt --write-media narration.mp3
npx hyperframes transcribe narration.mp3 --model small --language ko   # .en 모델 금지
```
- narration.mp3를 실제로 듣는다(또는 whisper 결과에서 오독 감지). 발음이 뭉개지는 단어 → script.txt 표기 수정 → TTS 재생성. (예: 한자어 연음, 외래어)

### S5. 타이밍 동기화
```bash
python3 bin/sync_timing.py --hi <강조어,쉼표구분>
```
- transcript.json + script.txt → `captions-data.js` (WORDS/CAPTION_GROUPS) 자동 생성 + **문장 테이블**(씬 경계) 출력.
- 후편집 2건: ① 자막 표시형 변환 (십오만→15만 — WORDS와 CAPTION_GROUPS 양쪽, hi 배열 포함) ② 그룹핑이 의미 단위에 어긋나면 수동 조정.
- 출력된 audio/root data-duration 제안값을 index.html에 반영.

### S6. 연출 — `scenes.js` + `index.html`
- **씬 경계 = S5 문장 테이블.** 씬 start = 문장 start − 0.2~0.4s(리드), dur는 다음 씬 start까지 + TRANSITION(0.45).
- **캐스팅은 기존 variant 6종**(host/king/admiral/militia/lady/kid) 안에서. 새 인물이 필요하면 모자·의상 색으로 변주. 여성=`{variant:"lady"}`(왕비는 `royal:true`+당의색, 아낙/기녀는 저고리·치마 색변주), 아이=`{variant:"kid"}`(배치 시 w×0.6~0.7). 모자 변주: king `hat:"myeonryu"`(면류관), militia `hat:"samo"`(사모+단령)·`"paeraengi"`(패랭이)·`"gulgeon"`(굴건 상복). **이 6종·모자 변주 밖의 새 variant 파츠(외국인 등) = 이 스킬 범위 밖**(별도 아트 세션 — PROJECT-NOTES 룩 프로세스 필수). ⚠ 사모는 중국 관모 오독 리스크 있어 단령 흉배 색·맥락으로 보강.
- **소품은 라이브러리 복사가 기본, 신규 작화는 예외.** 먼저 **`props-catalog.md`(전수 인덱스: 보유 자산→출처 파일 매핑)**에서 찾고, 해당 출처(`episodes/*/index.html`, `bench/*.html`)의 검증된 SVG를 복사-리컬러-변형한다. 카탈로그에 없는 소품만 새로 그리고, 새로 그린 소품은 검수 통과 후 카탈로그에 행을 추가한다.
- 새로 그릴 때: **실물의 구성 요소를 3~6개로 목록화**하고(예: 거중기 = 사다리꼴 틀 + 상/하 도르래 + 줄 + 매단 돌 + 양측 물레), 요소 하나당 `<g data-obj>` 하나로, **레퍼런스 트레이스**(프리핸드 금지 — PROJECT-NOTES 재발방지 §3), design.md 팔레트 준수. 요소 수가 아니라 시그니처 실루엣이 가독성을 만든다.
- **씬 구성 최소 규격 (전 씬 필수, 아웃트로 제외 — 숫자로 세서 검사한다. EP.4 sonnet5 세션에서 이 하한이 없어 "배경색+깃발 2개+캐릭터" 수준의 빈 화면이 나옴):**
  1. **3레이어**: ① 환경 레이어(하늘 요소 ≥1: 달·해·별·구름·비/눈, 또는 지면 디테일: 박석·물결·풀) ② 주 소품 1개 ③ 보조 소품 또는 배경 실루엣(언덕·성곽 실루엣·구름) ≥1. 배경 단색 + 소품 하나 + 캐릭터 = 불합격.
  2. **주 소품 크기 하한**: 렌더 폭 ≥ 380px(캔버스의 35%) 또는 높이 ≥ 500px. 그보다 작으면 주 소품이 아니라 장식이므로 하나 더 그리거나 키운다.
  3. **프리미티브 하한**: 주 소품 ≥ 12개 프리미티브·`data-obj` 그룹 ≥ 4 (EP.3 거중기 20개/7그룹, 성벽 30개/7그룹이 기준선). 보조 소품 ≥ 5개. 목록화한 구성 요소당 프리미티브 1개짜리 소품(깃대 rect 1 + 깃발 polygon 1 + 창날 polygon 1)은 실루엣만 남은 막대그림이다 — 요소마다 셰이드·디테일 프리미티브를 붙인다.
  4. **2톤 명암 필수**: 한 변 200px 이상의 면은 단색 금지 — 본색 + 셰이드(어둡거나 밝은 톤) 최소 1개. 지붕은 본체 path + 용마루/처마선 path 분리(파일럿 `shade()` 원칙). 벽은 몸체 + 기단/띠 하이라이트.
  5. **배경 대비**: 소품 주색과 stage 배경색의 명도 차가 눈에 보여야 한다 — 흑백으로 바꿨을 때 실루엣이 사라지면 불합격(밤 남색 배경에 암갈색 건물 금지 — EP.4 s3/s5에서 실제 발생). 어두운 씬의 건물은 윤곽 하이라이트나 밝은 창/문으로 분리한다.
- **스케일·지면 규칙 (전 씬 필수 — EP.4 sonnet5 세션에서 이 규칙이 없어 배치·크기 붕괴: 말이 어깨 높이, 전각이 캐릭터 크기로 공중 부양, 어좌가 캐릭터보다 작음):**
  1. **지면선 선언 먼저**: 씬 저작 시작 시 지면선 1개를 선언한다 — 기본 `bottom: 560px`(자막존+여유, EP.2·EP.3 전 씬 검증값). 서 있는 모든 것(캐릭터·건물·소품)의 하단을 지면선 ±100px에 스냅. 지면 접점 없는 오브젝트는 원경 실루엣(산·성곽 스카이라인)만 허용, 원경은 반드시 배경 밴드 상단(지평선) 위에 얹는다 — 공중 부양 금지.
  2. **물 밴드 위치**: 물은 지평선 위 원경이거나 캐릭터 발밑까지 내려오거나 둘 중 하나. 화면 중간을 가로지르는 물 밴드 '아래' 지면에 캐릭터가 서면 바다 밑/공중 물로 오독(EP.4 s6 제주 바다).
  3. **상대 스케일 표 — 캐릭터가 기준자다.** 캐릭터 렌더 높이 = `w × 1.2`(rig 200×240). w 380~440 기준 460~530px. 이 높이를 1로 두고:
     | 오브젝트 | 캐릭터 대비 높이 | 근거/위반 사례 |
     | --- | --- | --- |
     | 말·소 | 1.0~1.3 | EP.4 s1 말이 0.5 → 조랑말 오독 |
     | 단층 한옥·초가·군막 | 1.5~2.2 (처마·꼭짓점이 머리 위) | EP.4 s2 군막 1.2 → 왜소 |
     | 궁궐 전각·성문 (중경) | ≥ 2.2 | EP.4 s3 전각 ≈1.0 → 모형 오독 |
     | 어좌+단+병풍 세트 | 1.2~1.8 | EP.4 s7 어좌 <1 → 소품장 |
     | 문·창 (벽 요소) | 1.0~1.3 + 벽면 색 밴드 필수 | EP.4 s5 창이 허공에 |
     | 나무 (중경) | 1.5~2.5 | |
     | 대형 기계 (거중기류) | 1.4~1.8 | EP.3 검증값 ≈800px |
     | 손도구 | ≤ 0.5 | |
  4. **여백 배분**: 스냅샷에서 단색 빈 영역이 세로로 화면 절반 이상 이어지면 불합격 — 환경 레이어로 분산하거나 소품을 키운다(EP.4 s7 상단 60%가 빈 보라).
  5. **초안 편향 보정**: S6.5 인간 튜닝 이력상 LLM 초안은 소품을 체계적으로 작게·낮게 찍는다(EP.2 두루마리 ×1.81, EP.3 거중기 ×2.5로 확대 보정됨). 애매하면 표의 상한 쪽으로 키운다.
  6. **검증 좌표 프리셋 (EP.2·EP.3 인간 튜닝 통과본)**: 캐릭터 x 28~72% / bottom 560~660 / w 360~440. 2인 씬은 x≈30%+68%, bottom 660/640으로 미세 깊이. 풀블리드 배경 구조물(성벽류)은 폭 1080·bottom 560. 주 소품 지면 = bottom 560. 새 씬은 백지에서 찍지 말고 여기서 시작한다.
- **소품 오독 방지 규칙 (블라인드 벤치 실측 — bench/it1, 2026-07-12):**
  1. **핸드 소품 부착**: 손에 든 도구는 자루 끝이 캐릭터 손 원 중심에 닿게 그리고, 도구 헤드는 얼굴·머리와 절대 겹치지 않게 몸 바깥쪽으로 뺀다. 머리와 겹치면 "쓴 것/배경 소품"으로 오독된다(벤치: 망치→자귀 오독).
  2. **물에 뜨는 것(배)은 수면과 접촉**: 선체 하단이 물 밴드에 겹치고, 물결 라인 1개가 선체 앞을 지나게. 물 위 공중부양 금지.
  2-1. **역방향 — 물에 뜨지 않는 것은 물 밴드와 겹침 금지**: 인물·허수아비·건물의 발/기단은 항상 뭍(둑·모래·박석) 위에. 물결 라인이 인물 몸통을 가로지르면 "물에 빠진 사람"으로 읽힌다(it3 모내기 참사 — 농부·허수아비가 논물 밴드 위에 배치돼 "익사 구조 장면" 오독).
  2-2. **넓은 색 밴드의 의미론**: 화면 폭을 가로지르는 채도 높은 파란 밴드 = 무조건 강/바다로 읽힌다. 논물은 파란색 금지 — 하늘 반사 톤(회청록, 낮은 채도) + **두렁(논둑) 격자 라인** + 모가 수면의 30% 이상을 덮어야 논으로 읽힌다. 두렁이 논의 시그니처다.
  3. **시그니처 디테일 표** — 소품마다 "정체성을 결정하는 디테일 1개"를 반드시 넣는다. 실측된 것:
     | 소품 | 필수 시그니처 | 빠지면 오독되는 것 |
     | --- | --- | --- |
     | 초가지붕 | 짚결 스트로크 ≥2 + 처마 끝 들쭉(스캘럽) | 천막 |
     | 보따리 | 바닥 단독 배치 금지 — 막대에 매달거나(봇짐) 등에 멘 형태로. 바닥에 둘 땐 매듭 귀 2개+천 주름 | 항아리·쌀포대 (it1·it2 2연속 오독) |
     | 망치 | **양측 대칭의 넓은 블록 헤드**(자루와 다른 톤, 헤드 폭 ≥ 자루 3배) + 수직 자루. 한쪽으로 치우친 쐐기꼴은 도끼로 읽힘 | 자귀/도끼/손도끼 |
     | 초가 처마 들쭉 | 균일한 반원 스캘럽 연속 금지(성가퀴/배틀멘트로 읽힘) — 불규칙 지그재그 짚 프린지 + 짚결 스트로크 | 성벽 톱니 |

  4. **직업 정체성은 복식이 아니라 도구가 만든다**: 컷아웃 그림체에서 복식만으로는 역할이 안 읽힌다(벤치: 농부→"조선 남성", 군졸→"일반 남성"). 역할 있는 인물에겐 반드시 행위 소품을 붙인다 — 농부=지게·괭이·볏단 들기, 어부=그물(it2 성공 사례), 군인=무기, 궁수=활, 대장장이=망치+모루. 소품은 핸드 소품 부착 규칙대로 손에 쥐여준다.
  5. **도구 헤드 크기 하한**: 손도구(괭이·망치·도끼·낫)의 헤드 폭 ≥ 자루 굵기의 3배 + 자루와 다른 색. 헤드가 작으면 어깨에 걸쳐도 "막대/지팡이"로만 읽힌다(it4 괭이→막대 오독).
  6. **정체성이 중요한 소품은 원경에 두지 않는다**: 렌더 폭 200px 미만으로 줄어드는 원경 소품은 시그니처가 뭉개져 "집"·"덩어리"로만 읽힌다 — 원경은 무드용 실루엣(산·숲) 전용, 명명돼야 할 소품은 중경 이상 크기로.
  7. **앵커 소품 원칙**: 씬마다 "이 장소임을 결정하는 앵커 소품 1개"를 정하고(대장간=모루+망치, 주막=酒깃발, 우물가=우물) 그 소품을 가장 크고 명확하게 그린다. **앵커가 오독되면 부속 소품 전부가 그 프레임으로 연쇄 오염된다**(it5 실측: 모루→팬 오독 → 화로→오븐, 도구 거치대→바구니, "대장간"→"유목민 취사장").
  8. **기존 자산 재사용 시 시그니처 표 재대조**: 이전 에피소드/벤치 자산을 복사할 때, 그 자산이 표의 시그니처를 실제로 충족하는지 크롭 스크린샷으로 확인한다 — "이전에 통과했다" ≠ "시그니처 충족"(it1 모루는 hedge로 통과했던 것을 it5가 재사용해 참사).
  9. **이중 게이트 기준(sprint1 확립)**: 물리 소품·야외 행위 씬(낚시·대장간·파발)은 haiku 실루엣 게이트까지 기대 가능. **사회적 의례 씬(어전·사사·시험)의 '상황' 판독은 haiku에게 기대하지 않는다** — 이런 씬은 sonnet 게이트(명칭·고증) + 에피소드의 자막/스탬프가 상황을 전달한다. haiku 게이트의 합격 기준은 "다른 물건/장면으로의 **적극 오독**(모루→팬, 어전→무대, 측우기→나무통)이 없을 것"이지, 고유 명칭 명명이 아니다.
- **레이아웃 조정 대상 등록 (저작 규칙 — S6.5 튜너의 전제)**:
  - 모든 소품 요소에 저작 시점에 `data-adj="<씬id>-<이름>"` 직접 부여 (런타임 `ADJ_MAP` 등록 불필요; 캐릭터는 마운트 시 자동 부여).
  - 소품 내부는 논리 부위(층·지붕·몸체)만이 아니라 **시각적으로 독립된 세부 조각(몸돌·지붕돌·상륜 등)까지 전부 `<g data-obj="키">`로 중첩 그룹핑** — 튜너가 `[data-obj]`를 자동 노출하므로 그룹핑 입도가 곧 조정 입도다. 예: `pagoda-tier1` 안에 `pagoda-tier1-body`/`pagoda-tier1-roof`. 단 GSAP이 개별 애니메이트하는 자식은 그룹 금지(정적 transform과 충돌).
  - index.html 재작성 시 하단 **레이아웃 오버라이드 적용부(`window.__layout` 훅 블록)는 반드시 보존**하고, `layout-overrides.js`는 빈 오버라이드(`{}`)로 리셋한다.
- 지뢰 (전부 파일럿에서 실제로 밟음):
  1. 팔 회전은 GSAP `svgOrigin` 필수 — arm-l `"60 152"`, arm-r `"140 152"`. CSS transform-origin 금지.
  2. 스탬프류 슬램: CSS `visibility:hidden` + 타임라인 `tl.set visible` + scale 0→1 back.out. `fromTo` immediateRender pre-state를 inspector가 잡는다.
  3. 캔버스보다 큰 장식은 `overflow:hidden` 래퍼(`data-layout-ignore`) 안에. 자식에 attr 달아도 소용없음.
  4. 씬은 track 0/1 교대 + z-index 상승 + 0.45s 겹침. 퇴장 애니 금지(마지막 씬 제외).
  5. 자막 그룹은 밖에서 fade-out + `visibility:hidden` set (caption self-lint가 index.html에 내장돼 있음).
- 세로 레이아웃: viewport meta `width=1080, height=1920`, body/root 치수, big-year류 타이포 스케일 조정.

### S6.4. 렌더 전 프레임 자체 점검 (필수 — 기계적 체크리스트, 모델 무관 품질 재현 장치)
`npm run check` 통과 ≠ 화면이 멀쩡함(정적 인스펙터는 시각 문제를 못 잡는다). **일괄 점검이 아니라 씬 단위 루프다** — 씬 하나 저작을 마칠 때마다 그 씬 스냅샷 1장으로 즉시 점검하고 통과 후 다음 씬으로 넘어간다(전 씬을 다 쓰고 몰아서 보면 수정 왕복이 커져 "대충 통과"로 기운다 — EP.4 sonnet5 세션 실측). S6.5 직전에 전 씬 일괄 재캡처로 최종 확인:
```bash
npx hyperframes snapshot --at <씬별 대표시점,쉼표구분> --no-end --describe false -o <scratchpad>/snaps
```
대표 시점 = 각 씬에서 자막·스탬프·num-pop이 **모두 떠 있는 순간**(대개 start+dur−1.0 부근). 프레임마다 아래 항목을 순서대로 대조, 하나라도 걸리면 수정 → 재캡처 → 전 항목 통과까지 반복:
1. **자막존 겹침**: 소품/건물이 자막 pill 영역(`bottom:380px` 기준 + 2줄 높이 ~200px)에 걸리는가 → 소품 `bottom ≥ 560px`로 상향. (EP.2 암자·EP.3 성벽/책더미에서 실제 발생)
2. **스탬프·num-pop ↔ 캐릭터 겹침**: 텍스트 박스가 캐릭터 머리/몸을 가리는가 → 캐릭터 반대편 빈 구역으로 이동. (EP.3 목민심서 스탬프에서 실제 발생)
3. **색 동화**: 소품 색이 배경/바닥과 명도 차 없이 묻히는가 → 팔레트 내 대비색으로 재채색. (EP.3 베이지 책더미가 베이지 바닥에 묻힘)
4. **원형 캐릭터 머리 뒤 원형 소품(해·달) 금지** — 후광/모자로 오독. 머리와 겹치지 않는 좌우 상단 빈 공간으로. (EP.3 태양에서 실제 발생)
5. **3초 명명 테스트**: 새 소품을 보고 3초 안에 이름이 나오는가 — 안 나오면 장식 추가 대신 실물 시그니처 실루엣 1개(처마 반전·도르래·양태 등)를 강화.
6. **씬 최소 규격 재검**: S6의 "씬 구성 최소 규격" 5항목(3레이어·주 소품 폭 ≥380px·프리미티브 하한·2톤 명암·배경 대비)을 프레임 위에서 세어 본다. 스냅샷에서 빈 단색 영역이 화면의 절반을 넘으면 환경/보조 레이어 누락 신호다.
7. **스케일 새니티**: 캐릭터를 기준자로 프레임 내 모든 오브젝트의 실물 비례를 센다 — 말<캐릭터, 건물≤캐릭터, 어좌<캐릭터는 즉시 불합격, S6 상대 스케일 표와 재대조. (EP.4 s1 말·s3 전각·s7 어좌에서 실제 발생)
8. **부양 검사**: 지면 접점 없이 뜬 오브젝트(지면선에도 배경 밴드 상단에도 안 닿음)를 센다 — 원경 실루엣 외 0개여야 한다. 벽 요소(창·문)는 벽면 색 밴드 없이 단독 배치 금지. (EP.4 s3 전각·s5 감옥 창에서 실제 발생)
이 체크리스트는 S8 블라인드 검수의 사전 필터다 — 여기서 걸러지면 렌더 재작업 왕복이 사라진다. **어느 항목도 "그림체가 미니멀해서 괜찮다"로 면제하지 않는다 — 미니멀함은 팔레트와 셰이프 언어에서 오는 것이지 요소 개수 부족에서 오는 게 아니다.**

### S6.5. 인간 레이아웃 조정 (배치는 사람이 최종 결정)
LLM이 찍은 위치·크기는 초안일 뿐이다 — 렌더 전에 사용자가 `studio-layout.html`로 직접 드래그/슬라이더 조정한다. 이 단계를 건너뛰고 렌더하지 않는다.
1. 정적 서버 기동(background): `.claude/launch.json`의 `toon-pilot-static` — python http.server **3014** (hyperframes preview 3013 아님).
2. Claude in Chrome으로 `http://localhost:3014/studio-layout.html` 새 탭 오픈.
3. Telegram 알림(⏸ blocked): "레이아웃 조정 대기" + URL. 사용자 완료 신호까지 대기.
4. 완료 신호 후 **자동 회수** — `javascript_tool`(studio-layout 탭)로:
   ```js
   const L = document.querySelector("iframe").contentWindow.__layout;
   ({ layout: L.get(), objects: L.getObjects() })
   ```
   받은 JSON으로 `layout-overrides.js`를 로컬에서 조립해 저장한다(기존 파일과 동일 형식: 주석 헤더 + `var LAYOUT_OVERRIDES` + `var OBJECT_OVERRIDES` + window 노출 1줄). **`overridesText()` 원문 문자열 반환은 Chrome 확장 가드가 차단하므로 쓰지 말 것**(2026-07-11 실측). 탭이 닫혔으면 재오픈 — localStorage(`toon-layout-overrides-v2`) 자동저장분이 복원된다.
5. `npm run check` 재통과 확인 후 S7 진행.

### S8. 이중 검수 게이트 (고증·가독성)
```bash
for t in <훅> <씬2중반> <씬3중반> <씬4중반>; do
  ffmpeg -y -ss $t -i renders/<slug>.mp4 -frames:v 1 /tmp/frame-$t.png; done
```
1. **블라인드 readability**: 프레임 4장을 **컨텍스트 없는** 서브에이전트에게 "이 화면의 오브젝트를 전부 명명하라"만 시킨다. 의도한 이름(갓·한옥·거북선…)과 다르면 불합격 → 해당 오브젝트 재작업. 작화한 세션이 자기 검증하면 오독을 못 잡는다.
