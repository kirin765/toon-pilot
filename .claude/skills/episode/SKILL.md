# 삼십초 역사 — 원커맨드 에피소드

주제 입력 → `renders/<slug>.mp4` + 업로드 메타. 악플 3종(사실 오류·어눌한 말투·고증 논란)은 각각 게이트(S3·S4·S8)로 차단한다. **PROJECT-NOTES.md를 먼저 읽을 것** — 지뢰 원문과 아키텍처가 거기 있다.

## 포맷 (YouTube Shorts)

- **1080×1920 세로.** 파일럿(임진왜란)은 1920×1080 가로였다 — 새 에피소드는 세로로 제작하고, 파일럿의 배경 모티프(한옥·지도·바다·황혼 언덕·아웃트로)는 재배치해서 재사용한다: 캐릭터를 크게(w 380~480px), 상하 스택 구도, 배경 오브젝트는 상단 1/3.
- **Shorts 세이프존**: 우측 ~140px(액션 버튼)·하단 ~320px(제목/채널 UI)에 자막·스탬프 금지. `.cap-wrap`은 `bottom: 380px` 기준.
- **이해가 길이보다 우선한다**(2026-07-25 사용자 피드백) — 압축하느라 문장이 조밀해지면 문장을 쪼개고 영상을 늘리는 쪽을 택한다.
- **정보량 기본값 = 「중간」**(2026-07-26 사용자 피드백 — EP.21이 "너무 간단해서 내용이 빈약"). 사용자가 따로 지정하지 않으면 중간으로 만든다.

| 정보량 | 내레이션에 담는 사료 항목 | 목표 길이 | 어절 / 문장 | 씬 수 |
| --- | --- | --- | --- | --- |
| 간단 | 핵심 사실 1 + 반전 1 | 45~55s | 65~80 / 14~17 | 5~7 + 아웃트로 |
| **중간(기본)** | **핵심 사실 2~3 + 반전 1 + 뒷받침(수치·인물·후일담) 2~3** | **65~80s** | **90~110 / 19~23** | **8~10 + 아웃트로** |
| 상세 | 핵심 사실 3~4 + 반전 1~2 + 뒷받침 4~5 | 85~100s | 125~150 / 26~30 | 11~13 + 아웃트로 |

  **정보량의 실체는 어절 수가 아니라 "내레이션이 말하는 사료 항목의 개수"다.** 길이는 결과지 목표가 아니다.
  EP.21이 빈약했던 이유는 문장이 짧아서가 아니라 **facts.md의 F4·F9·F10을 화면 스탬프·num-pop으로만 밀어내고
  내레이션에서 뺐기 때문**이다(무리 300여 명 / 조정에 천거 / 낭도 1천 명·화랑 200여 명·진골 자제는 아예 미사용).
  → **S2에서 facts.md 항목별로 "내레이션 / 화면만 / 미사용"을 표로 정하고, 중간이면 내레이션 항목이 5개 이상이어야 한다.**
  스탬프·num-pop은 내레이션을 **보강**하는 것이지 대체하는 게 아니다.
  ⚠ 중간(65~80s)은 Shorts 이탈률과 맞바꾸는 선택이다 — 사용자가 명시적으로 택한 값이므로 임의로 줄이지 말 것.

## 파이프라인

### S0. 입력 확인
- 주제 + 에피소드 번호(시리즈 넘버링) + 이전 편 예고와의 연결 여부.
- **주제가 지정되지 않았으면 `episode-candidates.md`에서 고른다** — 후보별 훅·앵커 자산·약점·상태(🟢/🟡/🔴)와 기각 사유가 박제돼 있다. 기각 목록(🔴)은 사유가 확인된 것이므로 재검토하지 않는다. 새 주제를 채택하거나 기각하면 그 문서에 행을 갱신한다.
- **소재 거부 목록**: 동북공정 인접(고구려·발해 귀속 등 현재진행 분쟁 프레임), 근현대 정치(해방 이후), 위안부·독도처럼 정확해도 진영 싸움이 붙는 주제. 야사는 "야사임"을 자막에 명시하면 허용.

### S1. 사료 리서치 → `episodes/<slug>/facts.md`
- WebSearch/WebFetch로 수집. 우선순위: 우리역사넷(contents.history.go.kr) > 한국민족문화대백과(encykorea.aks.ac.kr) > 조선왕조실록DB(sillok.history.go.kr) > 기타.
- 산출: 사실 목록(연도·수치·인명·인과), **주장마다 출처 URL 2개**. 출처 1개뿐인 흥미 주장은 "야사/설" 라벨.
- 여기서 훅 후보 3개를 같이 뽑는다 (역설·반전·의외 수치).

### S2. 대본 → `script.txt`
구조 (한 줄 = 한 문장 = 씬 경계 후보):
```
1행  훅 (0–2s): 결말·역설 먼저. "○○한 왕이 있었습니다" / "조선 최악의 아침" 형.
     "오늘은 ~를 알아보겠습니다" 형 도입 금지.
본문  상황 → 전개 → 반전 (행 수 제한 없음 — 청취 가독성 규칙대로 쪼갠 문장 여러 개가 한 씬을 공유해도 된다).
     **담을 사실 개수는 위 「정보량」 표를 따른다**(기본=중간: 핵심 사실 2~3 + 반전 1 + 뒷받침 2~3).
     반전은 1개로 유지하되, 그 반전을 떠받치는 사료 항목을 충분히 깔아 줄 것.
끝-1행 펀치라인 (여운 or 유머).
끝행  고정 아웃트로: "삼십 초 역사. 다음 편이 궁금하면, 구독." (+ 다음 편 예고 변형 가능)
```
청취 가독성 규칙 (게이트 0 — 2026-07-25 사용자 피드백: LLM 초안이 30초 예산에 정보를 우겨넣느라 문장이 조밀해져 한 번에 이해가 안 됨. **길이를 늘려서라도 이해가 우선**):
- **한 문장 = 정보 1개.** 쉼표로 정보 2개를 잇지 않는다 — "불을 붙이면 로켓 백 발이 차례로 날아가는 수레, 설계자는 조선의 임금이었습니다"(문종 화차 초안 실례)는 두 문장으로 쪼갠다.
- **긴 관형절 금지**: 명사 앞 수식이 4어절을 넘으면 문장을 쪼갠다 — 듣는 사람은 수식이 다 끝나야 그게 무엇인지 알게 되므로 그 사이 내용을 기억에 쌓아야 한다.
- **도치·인용 후치 금지**: "실록은 적었죠. 그 제도는 모두 임금이 일러 준 것이었다"(같은 초안 실례) 같은 구조 대신 자연 어순으로 — "실록에는 ~라고 적혀 있죠".
- **판정 기준은 낭독이 아니라 첫 청취다**: 자막 없이 처음 듣는 사람이 한 번에 이해하는가로 검사한다. 눈으로 두 번 읽어야 풀리는 문장은 귀로는 절대 못 따라간다 — 재작성.
구어체 규칙 (어눌함 게이트 1/2):
- 문장 ≤ 12어절 권장(15 초과 금지). 총 어절·문장 수는 위 「정보량」 표를 따른다.
- **길이 예측식(EP.21 실측, 3점 검증 ±1s): `길이(s) ≈ 어절×0.49 + 문장수×1.18`.**
  ⚠ 스킬의 옛 가정(2.5어절/s)은 **틀렸다** — 실제 발화는 약 2.0어절/s이고, **문장 경계마다 약 1.2초의 쉼**이 붙는다.
  그래서 짧은 문장을 많이 쓰면 어절 수가 같아도 길이가 는다. 검증점: EP.20 70어절/10문장=47.1s,
  EP.21 초안 109/20=76.9s, 중간안 80/17=59.2s, 최종 69/16=53.2s. (`--file`의 줄바꿈은 길이에 영향 없음)
  → **대본을 쓰고 나면 이 식으로 길이를 먼저 계산하고 TTS를 돌린다**(EP.21은 안 해서 76.9s를 뽑고 되돌렸다).
- 어절 예산에 맞추려 정보를 압축하지 말 것 — 문장을 쪼개고 영상을 늘린다. 그래도 길면 **사실 항목을 통째로 빼되,
  뺀 항목이 정보량 표의 하한을 깨지 않는지 확인**할 것.
- 종결어미 다양화: ~습니다 연속 3회 금지, ~했죠/~인데요/명사 종결 섞기.
- **숫자·단위는 TTS가 읽을 한글로 표기** (십오만, 이십 일). 자막 표시형(15만, 20일)은 S5에서 변환.

### S3. 팩트체크 게이트 (사실 오류 차단)
- 대본의 모든 사실 주장(연도·수치·인명·인과)을 추출 → facts.md와 1:1 대조.
- facts.md에 없는 주장 = 대본에서 삭제하거나 S1로 돌아가 출처 2개 확보.
- 판정 기록을 `episodes/<slug>/factcheck.md`에 남긴다 (주장 → 출처 매핑 표).
- 통과 전에는 S4로 넘어가지 않는다.

### S4. TTS + 귀검증 (어눌함 게이트 2/2)
```bash
uvx edge-tts --voice ko-KR-InJoonNeural --rate=+6% --file script.txt --write-media narration.mp3
```
- **전사는 `npx hyperframes transcribe`(whisper.cpp)를 쓰지 말 것 — 두 가지가 동시에 깨진다**(EP.17 실측):
  ① 한글 음절이 토큰 경계에서 쪼개져 `transcript.json`에 **U+FFFD(�)로 박힌다**(EP.15 커밋본에도 있는 고질). 귀검증이 불가능해진다.
  ② 마지막 문장을 통째로 뭉갠다(지뢰 #33 재발) — 47.8s 오디오를 43.0s로 끊고 아웃트로 7단어를 같은 타임스탬프에 몰아넣었다.
- **대신 faster-whisper로 `transcript.json`을 직접 만든다**(단어 타임스탬프 포함, 텍스트 무손상):
```bash
uv run --with faster-whisper python - <<'EOF'
from faster_whisper import WhisperModel
import json
m = WhisperModel('medium', device='cpu', compute_type='int8')
segs,_ = m.transcribe('narration.mp3', language='ko', beam_size=5,
                      word_timestamps=True, vad_filter=False, condition_on_previous_text=False)
w=[{"text":x.word.strip(),"start":round(x.start,2),"end":round(x.end,2)}
   for s in segs for x in (s.words or []) if x.word.strip()]
json.dump(w, open('transcript.json','w'), ensure_ascii=False, indent=2)
print(len(w), w[-1])
EOF
```
  ⚠ `vad_filter=False` 필수 — 켜면 아웃트로 세그먼트를 떨어뜨린다. **마지막 단어가 script.txt 마지막 어절과 일치하는지 매번 대조**할 것.
- **귀검증**: 깨끗해진 전사에서 오독을 찾는다. **실단어로 붕괴하는 것만 위험**하고(지뢰 #32), 뜻 없는 철자 편향은 통과(스탬프로 보강). 붕괴 후보는 **2~3문맥 A/B**로 판별한 뒤 script.txt를 고쳐 TTS 재생성.

### S5. 타이밍 동기화
```bash
python3 bin/sync_timing.py --hi <강조어,쉼표구분>
```
- transcript.json + script.txt → `captions-data.js` (WORDS/CAPTION_GROUPS) 자동 생성 + **문장 테이블**(씬 경계) 출력.
- 후편집 2건: ① 자막 표시형 변환 (십오만→15만 — WORDS와 CAPTION_GROUPS 양쪽, hi 배열 포함) ② **자동 그룹핑 검수는 선택이 아니라 필수**(지뢰 #61): `CAPTION_GROUPS`의 text만 세로로 출력해 한 줄씩 읽어 보고, 조사·의존명사·수사에서 끊긴 곳이 있으면 **`caption-splits.txt`**(스크립트 문장당 한 줄, 그룹별 어절 수를 공백으로 구분)를 만들고 `sync_timing.py`를 다시 돌린다. 합이 문장 어절 수와 다르면 스크립트가 즉시 죽으니 오타 걱정은 없다. EP.26 실측: 자동 그룹은 19문장 중 10군데가 무의미 조각이었고 splits 지정으로 전량 해소.
- **`silencedetect`로 정렬 대조**(지뢰 #58): `ffmpeg -af silencedetect=n=-35dB:d=0.30`의 `silence_end` 목록과 CAPTION_GROUPS start를 대조해 **0.45초 이상 앞선 그룹만** 보정. 무음이 0건이면 보정 불필요.
- 출력된 audio/root data-duration 제안값을 index.html에 반영.

### S6. 연출 — `scenes.js` + `index.html`
- **S6.0 씬 플랜 표 먼저 — 배경은 씬마다 '장소'에서 도출한다** (지뢰 #62 — EP.24 sonnet5 세션에서 이 게이트가 없어 방 인젝터 1종을 7개 씬이 돌려쓰고, "궁중" 씬엔 궁궐 요소가 0개였다). 씬을 한 줄이라도 저작하기 전에 scenes.js 상단 주석에 표부터 완성한다:
  `| 씬 | 문장 요지 | 장소(고유명) | 시간대 | 배경 소스 | 앵커 소품 | 캐릭터 |`
  1. **장소는 고유명으로**: "실내"·"궁중" 같은 범주어 금지 — "죄인의 처소 방 안"·"궁궐 정전 앞마당"처럼 **앵커 소품이 자동으로 도출되는 수준**으로 적는다. 장소 칸을 채웠는데 앵커 소품 칸이 안 나오면 장소가 덜 구체적인 것.
  0. **배경 인젝터의 emit 순서를 산수로 검사한다**(지뢰 #69 — `npm run check` 0 에러로 통과하고 스냅샷에서만 보인다): 풀블리드 밴드(하늘·지면·벽·바닥)는 **항상 그 위에 서는 구조물보다 먼저** emit한다. 검사법 = 각 요소의 `bottom + height`를 세로로 나열해, **뒤에 오는 풀블리드 밴드가 앞 요소의 y 구간을 삼키는지** 계산할 것. EP.26에서 지면 밴드(height 930)가 동헌(bottom 560·height 795)보다 나중에 나와 건물의 y 990 이하가 전부 사라지고 **지붕만 남았다**. 권장 순서: 하늘 → 지면 → 지면 디테일 → 원경(담·능선) → 중경 건물 → 전경 소품.
  2. **배경 소스는 카탈로그 복사 우선**(소품과 동일 규칙): `props-catalog.md` §3(건물)·§5(지형지물)와 `episodes/*/index.html`에서 찾아 **출처 파일을 표에 적는다**. 신규 배경은 신규 소품과 같은 절차(구성 요소 목록화 + 검수 후 카탈로그 등재).
  3. **배경 종류 하한**: 아웃트로 제외 distinct 배경 ≥ 3종. 2종 이하면 장소 설계가 게으른 것 — 같은 서사도 방 안/마당/사립문 밖으로 쪼갤 수 있다.
  4. **동일 배경 연속 ≤ 3씬**: 서사가 같은 장소에 머물러도 4씬째는 변화를 넣는다 — 줌(벽면 클로즈업)·시간 경과(조명 톤)·다른 벽면/마당. 배경이 같은 연속 씬은 캐릭터 표정·포즈·신규 소품 등장 중 ≥1이 눈에 보이게 바뀌어야 한다 — **빈 방에서 소품 좌표만 바뀌는 씬 금지**.

     | **초가지붕** 보강 | 꼭대기로 살이 모이는 실루엣은 **게르·초분**이고, 그걸 낮추면 **버섯**이 된다. 정답은 **수평 용마름(둥근 가로 롤) + 사다리꼴 우진각 + 처마와 평행한 이엉 층결 3~4단 + 새끼줄 고사매기 + 두툼한 수평 처마 밴드**. ⚠ **용마름에서 처마로 퍼지는 방사 부채살은 파초·야자잎 지붕(동남아·오키나와) 문법**이고, 삼각 톱니 처마는 조선에 대응 실물이 없다 | 게르 · 버섯 · 초분 · 남아시아 흙집 |
     | **벽 선반** 보강 | ㄱ자 브래킷의 **상단 팔이 선반판 위로 솟으면 "선반 위에 놓인 회색 상자 2개"**가 된다 — 받침은 판 **아래**에. 선반 위 눕혀 쌓은 책은 **길이 편차 ≤16px**(60px면 제첨을 좌측 정렬해도 실루엣이 계단으로 읽힌다) | 계단 그래픽 · 회색 상자 |
     | **복합 서사 소품** | "피 묻은 칼+부러진 붓" 식 **의미 조합 소품 금지** — 벤치 17종 전원 오독. 컷아웃에서 서사는 소품 하나에 안 실린다: 소품은 단일 사물로, 서사는 장면 연출(인물+행위)·스탬프·자막으로 | (조합 전체가 불명·엉뚱한 단일물) |
     새 오독이 벤치·S8에서 발견되면 이 표에 행을 추가한다.

  4-1. **핸드 소품 배치는 rig 기하로 계산한다 — 눈대중 금지**(EP.6 실측: 초안이 몽둥이·붓을 손에서 200px 넘게 떨어뜨려 공중 부양). rig viewBox 200×240, 팔 피벗 arm-l `(60,152)` / arm-r `(140,152)`, 손 중심 arm-l `(60,200)` / arm-r `(140,200)`. 포즈 회전각을 적용해 손 위치를 구한 뒤 컴포지션 px로 변환:
     `손_viewBox = 피벗 + rot(θ)·(손중심 − 피벗)` → `x = charLeft + hx·(w/200)`, `y = charTop + hy·(w/200)`, `charTop = 1920 − bottom − w·1.2`.
     소품 svg는 자루 끝이 그 좌표에 오도록 `left`/`bottom`을 역산한다. **캐릭터는 항상 소품 위에 렌더되므로**(JS가 나중에 append) 소품은 몸 바깥으로 뻗은 부분만 보인다 — 뻗는 방향에 다른 캐릭터의 갓 챙이 없는지 확인할 것(갓 챙은 머리 원보다 넓다: viewBox x 28~172).
  4. **직업 정체성은 복식이 아니라 도구가 만든다**: 컷아웃 그림체에서 복식만으로는 역할이 안 읽힌다(벤치: 농부→"조선 남성", 군졸→"일반 남성"). 역할 있는 인물에겐 반드시 행위 소품을 붙인다 — 농부=지게·괭이·볏단 들기, 어부=그물(it2 성공 사례), 군인=무기, 궁수=활, 대장장이=망치+모루. 소품은 핸드 소품 부착 규칙대로 손에 쥐여준다.
  5. **도구 헤드 크기 하한**: 손도구(괭이·망치·도끼·낫)의 헤드 폭 ≥ 자루 굵기의 3배 + 자루와 다른 색. 헤드가 작으면 어깨에 걸쳐도 "막대/지팡이"로만 읽힌다(it4 괭이→막대 오독).
  6. **정체성이 중요한 소품은 원경에 두지 않는다**: 렌더 폭 200px 미만으로 줄어드는 원경 소품은 시그니처가 뭉개져 "집"·"덩어리"로만 읽힌다 — 원경은 무드용 실루엣(산·숲) 전용, 명명돼야 할 소품은 중경 이상 크기로.
  7. **앵커 소품 원칙**: 씬마다 "이 장소임을 결정하는 앵커 소품 1개"를 정하고(대장간=모루+망치, 주막=酒깃발, 우물가=우물) 그 소품을 가장 크고 명확하게 그린다. **앵커가 오독되면 부속 소품 전부가 그 프레임으로 연쇄 오염된다**(it5 실측: 모루→팬 오독 → 화로→오븐, 도구 거치대→바구니, "대장간"→"유목민 취사장").
  8. **기존 자산 재사용 시 시그니처 표 재대조**: 이전 에피소드/벤치 자산을 복사할 때, 그 자산이 표의 시그니처를 실제로 충족하는지 크롭 스크린샷으로 확인한다 — "이전에 통과했다" ≠ "시그니처 충족"(it1 모루는 hedge로 통과했던 것을 it5가 재사용해 참사).
  9. **이중 게이트 기준(sprint1 확립)**: 물리 소품·야외 행위 씬(낚시·대장간·파발)은 haiku 실루엣 게이트까지 기대 가능. **사회적 의례 씬(어전·사사·시험)의 '상황' 판독은 haiku에게 기대하지 않는다** — 이런 씬은 sonnet 게이트(명칭·고증) + 에피소드의 자막/스탬프가 상황을 전달한다. haiku 게이트의 합격 기준은 "다른 물건/장면으로의 **적극 오독**(모루→팬, 어전→무대, 측우기→나무통)이 없을 것"이지, 고유 명칭 명명이 아니다.
- **레이아웃 조정 대상 등록 (저작 규칙 — S6.5 튜너의 전제)**:
  - 모든 소품 요소에 저작 시점에 `data-adj="<씬id>-<이름>"` 직접 부여 (런타임 `ADJ_MAP` 등록 불필요; 캐릭터는 마운트 시 자동 부여).
  - 소품 내부는 논리 부위(층·지붕·몸체)만이 아니라 **시각적으로 독립된 세부 조각(몸돌·지붕돌·상륜 등)까지 전부 `<g data-obj="키">`로 중첩 그룹핑** — 튜너가 `[data-obj]`를 자동 노출하므로 그룹핑 입도가 곧 조정 입도다. 예: `pagoda-tier1` 안에 `pagoda-tier1-body`/`pagoda-tier1-roof`. 단 GSAP이 개별 애니메이트하는 자식은 그룹 금지(정적 transform과 충돌).
  - index.html 재작성 시 하단 **레이아웃 오버라이드 적용부(`window.__layout` 훅 블록)는 반드시 보존**하고, `layout-overrides.js`는 빈 오버라이드(`{}`)로 리셋한다.
- 지뢰 (전부 파일럿에서 실제로 밟음):
  1. 팔 회전은 GSAP `svgOrigin` 필수 — arm-l `"60 152"`, arm-r `"140 152"`. CSS transform-origin 금지.
  2. 스탬프류 슬램: CSS `visibility:hidden` + 타임라인 `tl.set visible` + scale 0→1 back.out. `fromTo` immediateRender pre-state를 inspector가 잡는다.
  3. 캔버스보다 큰 장식은 `overflow:hidden` 래퍼(`data-layout-ignore`) 안에. 자식에 attr 달아도 소용없음.
  4. 씬은 track 0/1 교대 + z-index 상승 + 0.45s 겹침. 퇴장 애니 금지(마지막 씬 제외).
  5. 자막 그룹은 밖에서 fade-out + `visibility:hidden` set (caption self-lint가 index.html에 내장돼 있음).
- 세로 레이아웃: viewport meta `width=1080, height=1920`, body/root 치수, big-year류 타이포 스케일 조정.

### S6.4. 렌더 전 프레임 자체 점검 (필수 — 기계적 체크리스트, 모델 무관 품질 재현 장치)
`npm run check` 통과 ≠ 화면이 멀쩡함(정적 인스펙터는 시각 문제를 못 잡는다). **일괄 점검이 아니라 씬 단위 루프다** — 씬 하나 저작을 마칠 때마다 그 씬 스냅샷 1장으로 즉시 점검하고 통과 후 다음 씬으로 넘어간다(전 씬을 다 쓰고 몰아서 보면 수정 왕복이 커져 "대충 통과"로 기운다 — EP.4 sonnet5 세션 실측). S6.5 직전에 전 씬 일괄 재캡처로 최종 확인:
```bash
npx hyperframes snapshot --at <씬별 대표시점,쉼표구분> --no-end --describe false -o <scratchpad>/snaps
```
대표 시점 = 각 씬에서 자막·스탬프·num-pop이 **모두 떠 있는 순간**(대개 start+dur−1.0 부근). 프레임마다 아래 항목을 순서대로 대조, 하나라도 걸리면 수정 → 재캡처 → 전 항목 통과까지 반복:
1. **자막존 겹침**: 소품/건물이 자막 pill 영역(`bottom:380px` 기준 + 2줄 높이 ~200px)에 걸리는가 → 소품 `bottom ≥ 560px`로 상향. (EP.2 암자·EP.3 성벽/책더미에서 실제 발생)
2. **스탬프·num-pop ↔ 캐릭터 겹침**: 텍스트 박스가 캐릭터 머리/몸을 가리는가 → 캐릭터 반대편 빈 구역으로 이동. (EP.3 목민심서 스탬프에서 실제 발생)
3. **색 동화**: ① **먼저 완전 동색인지 본다** — 소품 주색과 그 씬 배경색이 **같은 값**이면 소품이 "묻히는" 게 아니라 **통째로 사라지고 라벨·제첨 같은 부속만 허공에 뜬다**(지뢰 #70 — EP.26 소설 3권째가 벽과 동일한 `#1f2d45`였고, 검수자는 이를 "제첨이 책등 밖으로 넘쳤다"는 좌표 버그로 오진했다). 씬 배경색 목록과 소품 fill을 grep으로 대조할 것. ② 그다음 명도 차를 본다 → 팔레트 내 대비색으로 재채색. (EP.3 베이지 책더미가 베이지 바닥에 묻힘)
4. **원형 캐릭터 머리 뒤 원형 소품(해·달) 금지** — 후광/모자로 오독. 머리와 겹치지 않는 좌우 상단 빈 공간으로. (EP.3 태양에서 실제 발생)
5. **3초 명명 테스트**: 새 소품을 보고 3초 안에 이름이 나오는가 — 안 나오면 장식 추가 대신 실물 시그니처 실루엣 1개(처마 반전·도르래·양태 등)를 강화.
6. **씬 최소 규격 재검**: S6의 "씬 구성 최소 규격" 5항목(3레이어·주 소품 폭 ≥380px·프리미티브 하한·2톤 명암·배경 대비)을 프레임 위에서 세어 본다. 스냅샷에서 빈 단색 영역이 화면의 절반을 넘으면 환경/보조 레이어 누락 신호다.
7. **스케일 새니티**: 캐릭터를 기준자로 프레임 내 모든 오브젝트의 실물 비례를 센다 — 말<캐릭터, 건물≤캐릭터, 어좌<캐릭터는 즉시 불합격, S6 상대 스케일 표와 재대조. (EP.4 s1 말·s3 전각·s7 어좌에서 실제 발생)
8. **부양 검사**: 지면 접점 없이 뜬 오브젝트(지면선에도 배경 밴드 상단에도 안 닿음)를 센다 — 원경 실루엣 외 0개여야 한다. 벽 요소(창·문)는 벽면 색 밴드 없이 단독 배치 금지. (EP.4 s3 전각·s5 감옥 창에서 실제 발생)
9. **벽 요소 앵커 검사**: 문 하단이 지면선에 닿는가, 창 하단이 캐릭터 가슴 높이(지면선+420px) 이하인가 — 인물 머리보다 위에 통째로 떠 있는 문/창 = 불합격. (EP.24 창이 지면선+560px에서 실제 발생)
10. **장소 판독 검사**: 프레임만 보고 S6.0 씬 플랜 표의 '장소'가 맞혀지는가 — 궁이면 전각·월대·박석 중 ≥1, 방이면 벽 요소 2종이 프레임 안에 보여야 한다. "궁중"인데 하늘+구름+회색 바닥뿐이면 불합격. (EP.24 s3~s5에서 실제 발생)
11. **배경 중복 검사**: 직전 씬과 배경이 같으면 — 씬 플랜 표상 같은 장소가 맞는지, 동일 배경 4연속째가 아닌지, 이 씬에 눈에 보이는 변화(표정·포즈·신규 소품) ≥1이 있는지 확인.
이 체크리스트는 S8 블라인드 검수의 사전 필터다 — 여기서 걸러지면 렌더 재작업 왕복이 사라진다. **어느 항목도 "그림체가 미니멀해서 괜찮다"로 면제하지 않는다 — 미니멀함은 팔레트와 셰이프 언어에서 오는 것이지 요소 개수 부족에서 오는 게 아니다.**
