# toon-pilot — Thirty-Second History

**English** · [한국어](README.md)

A project that mass-produces South Park–style **paper cutout Korean history shorts** for the channel
"삼십초 역사" (Thirty-Second History) ([@history30sec](https://www.youtube.com/@history30sec)).
1080×1920 vertical, 45–100 seconds per episode.

Give it one topic and a single pipeline takes it from source research → script → fact-check → TTS →
staging → render → review → upload metadata. HTML + GSAP compositions are rendered to MP4 with
[HyperFrames](https://hyperframes.heygen.com).

> **If you are working as an agent, read `AGENTS.md` first.** This README is a human-facing overview;
> `AGENTS.md` is the source of truth. (Both are in Korean — that is the working language of this repo.)

## What's in here

- `episodes/` — EP.1–EP.31 archive (`facts.md` · `script.txt` · `scenes.js` · `index.html` · upload metadata)
- `characters.js` — character rig factory (6 `variant`s: host/king/admiral/militia/lady/kid)
- `scenes.js` — director scene JSON (per-scene start/dur/talker/chars/changes)
- `captions-data.js` — lip-sync `WORDS` + captions `CAPTION_GROUPS`
- `index.html` — assembles scene DOM, backgrounds, character mounts, and the timeline
- `bin/` — gate scripts (`check_script.py`, `check_composition.mjs`, `sync_timing.py`)
- `docs/` — pipeline, art rules, review prompts

## Architecture — three separated layers

| Layer | File | Who writes it |
| --- | --- | --- |
| rig | `characters.js` (+ `char-tuning.js`) | human — rarely touched |
| engine | `index.html` timeline builder | human — rarely touched |
| content | `script.txt` · `scenes.js` · scene/background parts | **generated by the LLM** |

Output is `renders/<slug>.mp4`; archives live in `episodes/<slug>/`. Progress is recorded in
`episodes/<slug>/STATE.md`.

## Pipeline (S0–S9)

| Stage | What happens | Gate |
| --- | --- | --- |
| S1 | source research → `facts.md` | 2 sources |
| S2 | script → `script.txt` | `bin/check_script.py` (awkward phrasing, length) |
| S3 | fact-check | claims ↔ `facts.md`, 1:1 |
| S4 | edge-tts + transcript ear-check | only real-word breakdown fails |
| S5 | timing sync (`sync_timing.py`) | — |
| S6 | staging `scenes.js` + `index.html` | `bin/check_composition.mjs` |
| S7 | render | 11-item frame checklist |
| S8 | blind review (period accuracy, readability) | **a reviewer with no context** |
| S9 | packaging · upload | — |

**If a gate fails, you do not move to the next stage.** Full procedure: `docs/EPISODE-PIPELINE.md`.

## Quick start

```bash
# gates (all must exit 0 before rendering)
python3 bin/check_script.py --density 중간   # script — before TTS
node bin/check_composition.mjs               # composition — before render
npm run check                                # hyperframes lint + validate + inspect
npm run gate                                 # all three at once

# production
uvx edge-tts --voice ko-KR-InJoonNeural --rate=+6% --file script.txt --write-media narration.mp3
python3 bin/sync_timing.py --hi <emphasis words, comma-separated>
npx hyperframes snapshot --at <t1,t2,...> --no-end --describe false -o <tmp>/snaps
npx hyperframes render --quality standard --output renders/<slug>.mp4

# tools
npm run dev                   # preview server (3013) — blocking. always run in background
python3 -m http.server 3014   # layout tuner (studio-layout.html)
npx hyperframes docs <topic>
```

## Hard rules (summary)

- **Determinism only** — no `Math.random()`, `Date.now()`, `fetch()`, or GSAP `repeat:-1`.
- Timed elements need `data-start` · `data-duration` · `data-track-index` plus `class="clip"`.
- Scenes alternate **track 0/1 + rising z-index + 0.45s overlap**.
- Rotate SVG arms with GSAP `svgOrigin`, never CSS `transform-origin` (`arm-l "60 152"` / `arm-r "140 152"`).
- No positional selectors (`:nth-child` · `:last-child`).
- Korean TTS is **edge-tts**. `npx hyperframes transcribe` corrupts Hangul — never use it.
- A human makes the final layout call — **never render without S6.5 (layout tuner)**.

Full constants and prohibitions: `docs/AGENT-QUICKREF.md`. The 74 real-world landmines actually stepped
on are indexed at the top of `PROJECT-NOTES.md`.
