# 에피소드 제작 파이프라인 — 삼십초 역사

주제 하나 → `renders/<slug>.mp4` + 업로드 메타. **이 문서가 파이프라인의 정본이다.**
어떤 모델·어떤 에이전트 하네스에서 실행하든 여기 적힌 스테이지 순서와 게이트를 그대로 따른다.

악플 3종(사실 오류 · 어눌한 말투 · 고증 논란)은 각각 게이트 **S3 · S4 · S8**이 막는다.
게이트는 완화 대상이 아니다 — 불합격이면 해당 스테이지로 되돌아간다.

## 0. 시작 전 (필수)

### 읽기 순서

| 순서 | 파일 | 언제 |
| --- | --- | --- |
| 1 | `AGENTS.md` | 항상 — 프로젝트 정체성·명령·아키텍처 |
| 2 | 이 문서 | 항상 |
| 3 | `PROJECT-NOTES.md` 상단 「지뢰 인덱스」 | 항상 (전문은 해당 지뢰를 만났을 때만) |
| 4 | `docs/ART-RULES.md` | S6 진입 시 — 씬을 한 줄이라도 쓰기 전에 |
| 5 | `props-catalog.md` | S6에서 소품·배경을 고를 때 |
| 6 | `episodes/<최근편>/` | 새 index.html을 쓸 때 참조 구현으로 |

컨텍스트가 좁은 모델은 3·4·5를 **스테이지 진입 시점에** 읽는다. 전부 미리 읽지 않아도 된다.

### 필요한 능력과 대체 수단

| 스테이지 | 필요한 능력 | 없을 때 |
| --- | --- | --- |
| S1 | 웹 검색 + 페이지 열람 | 사용자에게 `episodes/<slug>/facts.md`를 직접 채워 달라고 요청하고 **대기**. 추측으로 사료를 지어내지 않는다 |
| S4 | 셸(`uvx`, `uv`) | 사용자에게 명령을 그대로 전달해 실행 요청 |
| S6.4 | 이미지 판독(스냅샷 보기) | 체크리스트를 사용자에게 넘겨 프레임 검수 요청. **건너뛰지 않는다** |
| S6.5 | 브라우저 자동화 | 사용자가 튜너를 직접 열고 다운로드 버튼으로 `layout-overrides.js` 회수 (§S6.5 수동 경로) |
| S8 | 다른 세션/모델 호출 | `docs/BLIND-REVIEW-PROMPT.md`를 사용자에게 주고 **다른 채팅**에 프레임과 함께 붙여넣어 결과를 받아오게 함 |
| S9 | YouTube 업로드 토큰 | 메타만 만들고 업로드는 사용자에게 넘김 |

능력이 없어 스테이지를 건너뛴 경우 **최종 보고에 어느 게이트를 생략했는지 반드시 명시**한다.

## 포맷 (YouTube Shorts)

- **1080×1920 세로.** 파일럿(임진왜란)만 1920×1080 가로였다. 파일럿의 배경 모티프(한옥·지도·바다·황혼 언덕·아웃트로)는 세로로 재배치해 재사용한다: 캐릭터를 크게(w 380~480px), 상하 스택 구도, 배경 오브젝트는 상단 1/3.
- **Shorts 세이프존**: 우측 ~140px(액션 버튼)·하단 ~320px(제목/채널 UI)에 자막·스탬프 금지. `.cap-wrap`은 `bottom: 380px` 기준.
- **이해가 길이보다 우선한다.** 압축하느라 문장이 조밀해지면 문장을 쪼개고 영상을 늘리는 쪽을 택한다.
- **정보량 기본값 = 「중간」.** 사용자가 따로 지정하지 않으면 중간으로 만든다.

| 정보량 | 내레이션에 담는 사료 항목 | 목표 길이 | 어절 / 문장 | 씬 수 |
| --- | --- | --- | --- | --- |
| 간단 | 핵심 사실 1 + 반전 1 | 45~55s | 65~80 / 14~17 | 5~7 + 아웃트로 |
| **중간(기본)** | **핵심 사실 2~3 + 반전 1 + 뒷받침(수치·인물·후일담) 2~3** | **65~80s** | **90~110 / 19~23** | **8~10 + 아웃트로** |
| 상세 | 핵심 사실 3~4 + 반전 1~2 + 뒷받침 4~5 | 85~100s | 125~150 / 26~30 | 11~13 + 아웃트로 |

**정보량의 실체는 어절 수가 아니라 "내레이션이 말하는 사료 항목의 개수"다.** 길이는 결과지 목표가 아니다.
EP.21이 빈약했던 이유는 문장이 짧아서가 아니라 **facts.md의 항목을 화면 스탬프·num-pop으로만 밀어내고 내레이션에서 뺐기 때문**이다.
→ **S2에서 facts.md 항목별로 "내레이션 / 화면만 / 미사용"을 표로 정하고, 중간이면 내레이션 항목이 5개 이상이어야 한다.**
스탬프·num-pop은 내레이션을 **보강**하는 것이지 대체하는 게 아니다.
⚠ 중간(65~80s)은 Shorts 이탈률과 맞바꾸는 선택이다 — 사용자가 명시적으로 택한 값이므로 임의로 줄이지 말 것.

## S0. 입력 확인

- 주제 + 에피소드 번호(시리즈 넘버링) + 이전 편 예고와의 연결 여부.
- **주제가 지정되지 않았으면 `episode-candidates.md`에서 고른다** — 후보별 훅·앵커 자산·약점·상태(🟢/🟡/🔴)와 기각 사유가 박제돼 있다. 기각 목록(🔴)은 사유가 확인된 것이므로 재검토하지 않는다. 새 주제를 채택하거나 기각하면 그 문서에 행을 갱신한다.
- **소재 거부 목록**: 동북공정 인접(고구려·발해 귀속 등 현재진행 분쟁 프레임), 근현대 정치(해방 이후), 위안부·독도처럼 정확해도 진영 싸움이 붙는 주제. 야사는 "야사임"을 자막에 명시하면 허용.

## S1. 사료 리서치 → `episodes/<slug>/facts.md`

- 우선순위: 우리역사넷(contents.history.go.kr) > 한국민족문화대백과(encykorea.aks.ac.kr) > 조선왕조실록DB(sillok.history.go.kr) > 기타.
- 산출: 사실 목록(연도·수치·인명·인과), **주장마다 출처 URL 2개**. 출처 1개뿐인 흥미 주장은 "야사/설" 라벨.
- 여기서 훅 후보 3개를 같이 뽑는다 (역설·반전·의외 수치).
- ⚠ **다른 에이전트가 보고한 실록 기사 ID·한문 원문은 지어질 수 있다 — 인용은 반드시 직접 열어 대조**(지뢰 #38). 역방향도 마찬가지로, "사료에 없음" 판정도 검증한다(지뢰 #39).
- ⚠ **후보 문서(`episode-candidates.md`)의 '왜'도 그대로 믿지 말 것** — 인과가 사료와 정반대일 수 있다(지뢰 #59).

## S2. 대본 → `script.txt`

구조 (한 줄 = 한 문장):

```
1행  훅 (0–2s): 결말·역설 먼저. "○○한 왕이 있었습니다" / "조선 최악의 아침" 형.
     "오늘은 ~를 알아보겠습니다" 형 도입 금지.
본문  상황 → 전개 → 반전 (행 수 제한 없음 — 쪼갠 문장 여러 개가 한 씬을 공유해도 된다).
     담을 사실 개수는 위 「정보량」 표를 따른다. 반전은 1개로 유지하되 떠받치는 사료를 충분히 깐다.
끝-1행 펀치라인 (여운 or 유머).
끝행  고정 아웃트로: "삼십 초 역사. 다음 편이 궁금하면, 구독."
```

**청취 가독성 규칙 (게이트 0)** — LLM 초안은 예산에 정보를 우겨넣느라 문장이 조밀해져 한 번에 이해가 안 된다. **길이를 늘려서라도 이해가 우선:**

- **한 문장 = 정보 1개.** 쉼표로 정보 2개를 잇지 않는다.
- **긴 관형절 금지**: 명사 앞 수식이 4어절을 넘으면 쪼갠다 — 듣는 사람은 수식이 끝나야 그게 무엇인지 안다.
- **도치·인용 후치 금지**: "실록은 적었죠. 그 제도는 모두 임금이 일러 준 것이었다" 대신 자연 어순으로.
- **판정 기준은 낭독이 아니라 첫 청취다.** 눈으로 두 번 읽어야 풀리는 문장은 귀로는 못 따라간다 — 재작성.

**구어체 규칙 (어눌함 게이트 1/2):**

- 문장 ≤ 12어절 권장(15 초과 금지).
- **길이 예측식: `길이(s) ≈ 어절×0.49 + 문장수×1.18`** (4점 검증, 오차 ±1.4s). 문장 = 줄이 아니라 **마침표** 단위 — edge-tts의 묵음은 줄바꿈이 아니라 마침표에 붙는다(지뢰 #34 정정).
- 어절 예산에 맞추려 정보를 압축하지 말 것 — 문장을 쪼개고 영상을 늘린다. 그래도 길면 **사실 항목을 통째로 빼되** 정보량 표의 하한을 깨는지 확인.
- 종결어미 다양화: ~습니다 연속 3회 금지, ~했죠/~인데요/명사 종결 섞기.
- **숫자·단위는 TTS가 읽을 한글로 표기**(십오만, 이십 일). 자막 표시형(15만, 20일)은 S5에서 변환.

### 게이트 — 대본은 기계로 검사한 뒤 TTS에 넘긴다

```bash
python3 bin/check_script.py --density 중간      # exit 0 이어야 S4로
```

예측 길이·문장별 어절 수·아라비아 숫자·종결어미 연속·훅/아웃트로 형식을 검사한다.
**TTS를 돌리기 전에 통과시킨다** — 여기서 잡으면 재생성 왕복이 없다.

## S3. 팩트체크 게이트 (사실 오류 차단)

- 대본의 모든 사실 주장(연도·수치·인명·인과)을 추출 → `facts.md`와 1:1 대조.
- facts.md에 없는 주장 = 대본에서 삭제하거나 S1로 돌아가 출처 2개 확보.
- 판정 기록을 `episodes/<slug>/factcheck.md`에 남긴다 (주장 → 출처 매핑 표).
- **자체 팩트체크는 facts.md 자체의 오류를 못 잡는다**(지뢰 #31) — 가능하면 사료를 새로 여는 **적대적 검증자**(다른 세션/모델)를 붙인다.
- 통과 전에는 S4로 넘어가지 않는다.

## S4. TTS + 귀검증 (어눌함 게이트 2/2)

```bash
uvx edge-tts --voice ko-KR-InJoonNeural --rate=+6% --file script.txt --write-media narration.mp3
```

- **전사는 `npx hyperframes transcribe`(whisper.cpp)를 쓰지 말 것** — 한글을 U+FFFD로 깨뜨리고 마지막 문장을 뭉갠다(지뢰 #53·#33).
- **faster-whisper로 `transcript.json`을 직접 만든다:**

```bash
uv run --with faster-whisper python - <<'EOF'
from faster_whisper import WhisperModel
import json
m = WhisperModel('medium', device='cpu', compute_type='int8')
segs,_ = m.transcribe('narration.mp3', language='ko', beam_size=5,
                      word_timestamps=True, vad_filter=False, condition_on_previous_text=False)
w=[{"text":x.word.strip(),"start":round(x.start,2),"end":round(x.end,2)}
   for s in segs for x in (s.words or []) if x.word.strip()]
json.dump(w, open('transcript.json','w'), ensure_ascii=False, indent=2)
print(len(w), w[-1])
EOF
```

- ⚠ `vad_filter=False` 필수 — 켜면 아웃트로 세그먼트를 떨어뜨린다.
- **끝단어 대조는 기계로:**

```bash
python3 bin/check_script.py --transcript      # 전사 마지막 단어 == 대본 마지막 어절
```

- **귀검증**: 전사에서 오독을 찾는다. **실단어로 붕괴하는 것만 위험**하고(지뢰 #32), 뜻 없는 철자 편향은 통과(스탬프로 보강). 붕괴 후보는 **2~3문맥 A/B**로 판별한 뒤 script.txt를 고쳐 TTS 재생성. (실측: "부하"→"부화", "금오"→"금호")

## S5. 타이밍 동기화

```bash
python3 bin/sync_timing.py --hi <강조어,쉼표구분>
```

- `transcript.json` + `script.txt` → `captions-data.js`(WORDS/CAPTION_GROUPS) 자동 생성 + **문장 테이블**(씬 경계) 출력.
- 후편집 2건:
  1. 자막 표시형 변환(십오만→15만 — WORDS·CAPTION_GROUPS 양쪽, hi 배열 포함). **작은 수도 빠뜨리지 말 것**(지뢰 #10).
  2. **자동 그룹핑 검수는 선택이 아니라 필수**(지뢰 #61): `CAPTION_GROUPS`의 text만 세로로 출력해 한 줄씩 읽고, 조사·의존명사·수사에서 끊긴 곳이 있으면 **`caption-splits.txt`**(스크립트 문장당 한 줄, 그룹별 어절 수를 공백 구분)를 만들고 `sync_timing.py`를 다시 돌린다. 합이 문장 어절 수와 다르면 스크립트가 즉시 죽으니 오타 걱정은 없다. (EP.26 실측: 19문장 중 10군데가 무의미 조각)
- **`silencedetect`로 정렬 대조**(지뢰 #58): `ffmpeg -af silencedetect=n=-35dB:d=0.30`의 `silence_end` 목록과 CAPTION_GROUPS start를 대조해 **0.45초 이상 앞선 그룹만** 보정. 무음이 0건이면 보정 불필요. 구간별 리맵 시 **경계값이 앞 구간에 잡히지 않는지** 확인(지뢰 #61 부수).
- 출력된 audio/root `data-duration` 제안값을 index.html에 반영.

## S6. 연출 — `scenes.js` + `index.html`

> **먼저 `docs/ART-RULES.md`를 연다.** 씬 최소 규격·스케일 표·시그니처 오독 표가 거기 있고, 이 스테이지 산출물은 그 규격으로 검사된다.

### S6.0 씬 플랜 표 먼저 — 배경은 씬마다 '장소'에서 도출한다

지뢰 #62: 이 게이트가 없으면 방 인젝터 1종을 씬 7개가 돌려쓰고 "궁중" 씬에 궁궐 요소가 0개가 된다.
씬을 한 줄이라도 저작하기 전에 `scenes.js` 상단 주석에 표부터 완성한다:

`| 씬 | 문장 요지 | 장소(고유명) | 시간대 | 배경 소스 | 앵커 소품 | 캐릭터 |`

1. **장소는 고유명으로**: "실내"·"궁중" 같은 범주어 금지 — "죄인의 처소 방 안"·"궁궐 정전 앞마당"처럼 **앵커 소품이 자동으로 도출되는 수준**으로. 장소 칸을 채웠는데 앵커 소품 칸이 안 나오면 장소가 덜 구체적인 것.
2. **배경 인젝터의 emit 순서를 산수로 검사한다**(지뢰 #69): 풀블리드 밴드(하늘·지면·벽·바닥)는 **항상 그 위에 서는 구조물보다 먼저** emit한다. 각 요소의 `bottom + height`를 세로로 나열해 뒤에 오는 밴드가 앞 요소의 y구간을 삼키는지 계산. 권장 순서: 하늘 → 지면 → 지면 디테일 → 원경(담·능선) → 중경 건물 → 전경 소품. (`bin/check_composition.mjs`가 자동 검사)
3. **배경 소스는 카탈로그 복사 우선**: `props-catalog.md` §3(건물)·§5(지형지물)와 `episodes/*/index.html`에서 찾아 **출처 파일을 표에 적는다**. 신규 배경은 신규 소품과 같은 절차.
4. **배경 종류 하한**: 아웃트로 제외 distinct 배경 ≥ 3종.
5. **동일 배경 연속 ≤ 3씬**: 4씬째는 줌·시간 경과·다른 벽면으로 변주. 배경이 같은 연속 씬은 캐릭터 표정·포즈·신규 소품 중 ≥1이 눈에 보이게 바뀌어야 한다 — **빈 방에서 소품 좌표만 바뀌는 씬 금지**.
6. **내레이션↔배경 대조**: 문장이 장소·상황 전환을 말하면 배경도 그 문장에서 바뀐다.
7. **무인(캐릭터 0명) 씬은 연속 2씬까지**, 인포그래픽 목적일 때만 — 문장에 행위 주체가 있으면 그 행위자를 rig로 세운다.

### S6.1 씬 경계·캐스팅

- **씬 경계 = S5 문장 테이블.** 씬 start = 문장 start − 0.2~0.4s(리드), dur는 다음 씬 start까지 + TRANSITION(0.45).
- **캐스팅은 기존 variant 6종**(host/king/admiral/militia/lady/kid) 안에서. 새 인물은 모자·의상 색으로 변주.
  여성=`{variant:"lady"}`(왕비는 `royal:true`+당의색), 아이=`{variant:"kid"}`(배치 시 w×0.6~0.7).
  모자 변주: king `hat:"myeonryu"`(면류관), militia `hat:"samo"`(사모+단령)·`"paeraengi"`(패랭이)·`"gulgeon"`(굴건 상복).
  **이 6종·모자 변주 밖의 새 variant 파츠(외국인 등) = 이 파이프라인 범위 밖**(별도 아트 세션).
  ⚠ 사모는 중국 관모 오독 리스크 — 단령 흉배 색·맥락으로 보강.
- **직업/신분 전환은 모자까지 갈아입힌다**(지뢰 #11) — 승려·삭발 등으로 신분이 바뀌는데 갓을 그대로 두면 서사가 깨진다.

### S6.2 소품 — 고증도 팩트체크 대상이다

- **소품 선정은 facts.md 재대조 대상이다**(지뢰 #27): "재산도 딸 아들 똑같이"를 엽전으로 그렸다가 시대착오 적발(조선 전기는 화폐 유통 실패기, 엽전은 상평통보 1678~). **소품 목록을 정한 뒤 facts.md를 다시 읽고 그 시대에 그 물건이 있었는지 확인.**
- **실물 유물 인서트는 원래 형식대로 마운트**(지뢰 #29): 「몽유도원도」는 족자가 아니라 횡권.
- **기존 자산도 용도가 바뀌면 고증이 바뀐다**(지뢰 #28): 동헌(관청)의 단청 기둥은 맞지만 처가(사가)에 복사하면 틀림.
- **소품은 라이브러리 복사가 기본, 신규 작화는 예외.** 먼저 **`props-catalog.md`**(전수 인덱스: 자산→출처 파일 매핑)에서 찾고, 해당 출처(`episodes/*/index.html`, `bench/*.html`)의 검증된 SVG를 복사-리컬러-변형한다. 새로 그린 소품은 검수 통과 후 카탈로그에 행을 추가한다.
- 새로 그릴 때: **실물의 구성 요소를 3~6개로 목록화**하고 요소 하나당 `<g data-obj>` 하나로, **레퍼런스 트레이스**(프리핸드 금지), `design.md` 팔레트 준수.
  ⚠ **모델은 지침의 하한선까지만 그린다**(지뢰 #16) — "요소 3~6개 목록화"만 지키면 요소당 프리미티브 1개짜리 막대그림이 나온다. `docs/ART-RULES.md`의 프리미티브 하한을 반드시 함께 적용.

### S6.3 규격 — `docs/ART-RULES.md`

씬 구성 최소 규격 · 스케일/지면 규칙 · 소품 오독 방지(시그니처 표) · 레이아웃 조정 대상 등록 · 저작 지뢰 5종은 전부 그 문서에 있다. **씬마다 숫자로 세서 대조한다.**

### 게이트 — 컴포지션 정적 검사

```bash
node bin/check_composition.mjs      # exit 0 이어야 S6.4로
npm run check                        # hyperframes lint + validate + inspect (에러 0 필수)
```

`bin/check_composition.mjs`는 `npm run check`가 **0 에러로 통과시키는** 결함을 잡는다:
스크립트 로드 누락(지뢰 #54) · 씬/트랙/z-index/타이밍 드리프트 · 배경 다양성(지뢰 #62) ·
풀블리드 emit 순서(지뢰 #69) · 색 동화(지뢰 #70) · 자막 안전존 · 캐스팅 화이트리스트 · 결정론 위반.

## S6.4 렌더 전 프레임 자체 점검 (필수)

`npm run check` 통과 ≠ 화면이 멀쩡함(정적 인스펙터는 시각 문제를 못 잡는다).
**일괄 점검이 아니라 씬 단위 루프다** — 씬 하나 저작을 마칠 때마다 그 씬 스냅샷 1장으로 즉시 점검하고 통과 후 다음 씬으로 간다. 전 씬을 다 쓰고 몰아 보면 수정 왕복이 커져 "대충 통과"로 기운다.

```bash
npx hyperframes snapshot --at <씬별 대표시점,쉼표구분> --no-end --describe false -o <tmp>/snaps
```

대표 시점 = 각 씬에서 자막·스탬프·num-pop이 **모두 떠 있는 순간**(대개 start+dur−1.0 부근).
프레임마다 아래를 순서대로 대조, 하나라도 걸리면 수정 → 재캡처 → 전 항목 통과까지 반복:

1. **자막존 겹침**: 소품/건물이 자막 pill 영역(`bottom:380px` + 2줄 ~200px)에 걸리는가 → 소품 `bottom ≥ 560px`.
2. **스탬프·num-pop ↔ 캐릭터 겹침**: 텍스트 박스가 캐릭터를 가리는가 → 반대편 빈 구역으로.
3. **색 동화**: ① **먼저 완전 동색인지 본다** — 소품 주색과 씬 배경색이 **같은 값**이면 소품이 통째로 사라지고 라벨·제첨만 허공에 뜬다(지뢰 #70). ② 그다음 명도 차 → 팔레트 내 대비색으로 재채색.
4. **원형 캐릭터 머리 뒤 원형 소품(해·달) 금지** — 후광/모자로 오독.
5. **3초 명명 테스트**: 새 소품을 보고 3초 안에 이름이 나오는가 — 안 나오면 장식 추가 대신 시그니처 실루엣 1개를 강화.
6. **씬 최소 규격 재검**: `docs/ART-RULES.md` §1의 5항목을 프레임 위에서 세어 본다. 빈 단색 영역이 화면 절반을 넘으면 환경/보조 레이어 누락 신호.
7. **스케일 새니티**: 캐릭터를 기준자로 실물 비례를 센다 — 말<캐릭터, 건물≤캐릭터, 어좌<캐릭터는 즉시 불합격.
8. **부양 검사**: 지면 접점 없이 뜬 오브젝트는 원경 실루엣 외 0개.
9. **벽 요소 앵커 검사**: 문 하단이 지면선에 닿는가, 창 하단이 지면선+420px 이하인가.
10. **장소 판독 검사**: 프레임만 보고 S6.0 표의 '장소'가 맞혀지는가 — 궁이면 전각·월대·박석 중 ≥1, 방이면 벽 요소 2종.
11. **배경 중복 검사**: 직전 씬과 배경이 같으면 — 같은 장소가 맞는지, 4연속째가 아닌지, 눈에 보이는 변화 ≥1이 있는지.

이 체크리스트는 S8의 사전 필터다. **어느 항목도 "그림체가 미니멀해서 괜찮다"로 면제하지 않는다** — 미니멀함은 팔레트와 셰이프 언어에서 오는 것이지 요소 개수 부족에서 오는 게 아니다.

## S6.5 인간 레이아웃 조정 (배치는 사람이 최종 결정)

LLM이 찍은 위치·크기는 초안이다. 렌더 전에 사용자가 `studio-layout.html`로 직접 조정한다. **이 단계를 건너뛰고 렌더하지 않는다.**

1. 정적 서버 기동(백그라운드): `python3 -m http.server 3014` (hyperframes preview 3013과 다른 포트).
2. **튜너 localStorage 클리어 필수**(지뢰 #17): `layout-overrides.js`를 비우는 것만으로는 부족 — 튜너가 localStorage의 **이전 에피소드 오버라이드를 iframe 위에 복원**해 회수 데이터를 오염시킨다. 튜너 오픈 직후 실행:
   ```js
   ["toon-layout-overrides-v1","toon-layout-overrides-v2","toon-layout-outline"]
     .forEach(k=>localStorage.removeItem(k)); location.reload();   // char-tuning-v1은 보존
   ```
3. 사용자에게 `http://localhost:3014/studio-layout.html`을 알리고 **완료 신호까지 대기**한다.
4. 완료 후 회수:
   - **브라우저 자동화가 있으면** 튜너 탭에서 실행:
     ```js
     const L = document.querySelector("iframe").contentWindow.__layout;
     ({ layout: L.get(), objects: L.getObjects() })
     ```
     받은 JSON으로 `layout-overrides.js`를 조립해 저장(주석 헤더 + `var LAYOUT_OVERRIDES` + `var OBJECT_OVERRIDES` + window 노출 1줄).
     ⚠ `overridesText()` 원문 문자열 반환은 브라우저 확장 가드에 막힐 수 있다.
   - **없으면(수동 경로)**: 사용자에게 튜너의 다운로드 버튼으로 받은 내용을 붙여 달라고 요청해 그대로 `layout-overrides.js`에 쓴다.
   - 회수 시 `L.list()`의 유효 키로 필터링해 stale 키를 제거한다.
5. `node bin/check_composition.mjs && npm run check` 재통과 확인 후 S7.

## S7. 렌더

```bash
npm run check
npx hyperframes render --quality standard --output renders/<slug>.mp4
```

렌더는 오래 걸린다 — 로컬이 느리면 우분투 홈서버에서 돌린다(`AGENTS.md` 참조).

## S8. 이중 검수 게이트 (고증·가독성)

```bash
for t in <훅> <씬2중반> <씬3중반> <씬4중반>; do
  ffmpeg -y -ss $t -i renders/<slug>.mp4 -frames:v 1 /tmp/frame-$t.png; done
```

1. **블라인드 readability** — `docs/BLIND-REVIEW-PROMPT.md`를 그대로 써서 **컨텍스트 없는** 검수자(다른 세션·다른 모델·사람)에게 프레임 4장을 보이고 "이 화면의 오브젝트를 전부 명명하라"만 시킨다.
   - **작화한 세션이 자기 검증하면 오독을 못 잡는다.** 반드시 분리한다.
   - ⚠ **검수자의 프레임↔씬 서술과 픽셀 좌표는 신뢰하지 말 것**(지뢰 #72). 유효한 것은 "무엇으로 보이는가"뿐 — 지적 위치는 직접 크롭해 확인한 뒤 판정한다. 단, 설명이 틀렸다고 지적 자체를 기각하지 말 것.
   - ⚠ **검수자의 확신도는 통과 근거가 아니다** — 블라인드 벤치 180종 실측에서 오독의 63%가 확신도 '상'이었다. 판정은 명명 일치 여부로만.
   - 의도한 이름과 다르면 불합격 → 해당 오브젝트 재작업.
2. **고증 체크**: 같은 프레임을 "한국사 배경 숏폼인데 중국식·일본식으로 오독될 복식/건축/기물 요소가 있는가"로 검사. 지적 요소는 수정.
   (컷아웃 그림체가 고증 기대치를 낮춰주지만, 명백한 타국 문법 — 변발·기모노 깃·중국식 처마 — 은 악플 트리거)
   고증 검수는 미술이 못 보는 렌더 버그도 잡는다(지뢰 #68).
